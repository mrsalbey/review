## **Регистры накопления**

1. Денежные средства.
	- [ ] Вид регистра *Остатки*.
	- [ ] Измерения регистра обязательны для заполнения.
2. Безналичная оплата.
	- [ ] Вид регистра *Обороты*.
	- [ ] Измерения регистра обязательны для заполнения.
3. Учет затрат.
	- [ ] Вид регистра *Обороты*.
	- [ ] Измерение регистра обязательно для заполнения.
4. Товары на складах.
	- [ ] В регистр добавлено измерение *Срок годности* с типом *Дата*. Отсутствует запрет незаполненных значений.

## **Документы**

1. Поступление товаров.
	- [ ] В табличную часть добавлен реквизит *Срок годности* с типом *Дата*. Реквизит выведен на форму и доступен для ручного изменения.
	- [ ] При формировании движений по регистру *Товары на складах* измерение *Срок годности*  заполняется данными из табличной части при значении учетной политики *FEFO* и остается не заполненным —  при учете *По среднему*. Значение учетной политики определяется на дату документа.
	- [ ] В обработке проведения запрос не содержит неиспользуемых полей и итогов, например, *Цена*.
	- [ ] Документ не формирует движения по регистру сведений *Цены номенклатуры поставщиков*, который отсутствует в техническом задании.
2. Реализация товаров и услуг.
	- [ ] Перед обращением к остаткам регистра *Товары на складах* записывается пустой набор записей, а также не записываются пустые наборы для остальных регистров накопления.
	- [ ] Установлена блокировка на регистр *Товары на складах*. Блокировка осуществляется  по номенклатуре из табличной части и по складу.
	- [ ] В запросе не инициализируется неиспользуемый *Менеджер временных таблиц*.
	- [ ] В запросе установлен отбор по текущему документу для табличных частей *Товары* и *Услуги*.
	- [ ] В запросе временная таблица индексируется по полям, участвующим при соединении с основным запросом. В общем и целом, поля *Номенклатура* и *Склад*.
	- [ ] Данные для формирования движений по регистрам выбираются одним запросом.
	- [ ] Переменная со значением константы запрета проведения при отрицательных остатках инициализируется до цикла обработки результата запроса.
	- [ ] При возникновении отрицательных остатков в момент проведения формируются два вида сообщения пользователю — подробное сообщение, какой номенклатуры и в каком количестве не хватает (при запрете) и сообщение о том, что образовались отрицательные остатки (при разрешении).
	- [ ] Для вывода в сообщения используются представления ссылочных полей запроса.
	- [ ] Движения по регистру *Продажи* формируются по табличным частям *Товары* и *Услуги*.
	- [ ] Сумма движений документа по регистру *Товары на складах* равна сумме движений по регистру *Учет затрат*.
	- [ ] При реализации товара в количестве большем, чем есть на остатке, при условии, что такое списание разрешено, формируется запись регистра *Товары на складах* на количество превышения с незаполненными значениями *Срок годности* и *Сумма*. Остальные измерения и ресурсы заполнены. Выводится сообщение об образовании отрицательных остатков.
	- [ ] При реализации отсутствующего товара на складе не формируется дополнительная запись регистра *Товары на складах* с незаполненными ресурсами *Количество* и *Сумма*, а так же с незаполненным измерением *Срок годности*.
	- [ ] При запрете проведения документа с отрицательными остатками формируется сообщение пользователю с детальным описанием. Документ не проводится.
	- [ ] При проведении документа формируется одна запись по регистру *Заказы клиентов* на итоговую сумму услуг при условии, что реализация введена на основании заказа клиента. А также, не формируется запись с нулевым значением ресурса *Сумма* при отсутствии услуг. Сумма услуг записана в ресурс *Сумма (факт)*.
	- [ ] При многократном проведении документа движения регистров замещают предыдущие записи.
3. Поступление услуг.
	- [ ] Для реквизита *Поставщик* не установлен отбор по типу контрагента.
	- [ ] Для реквизита *Договор контрагента* настроена связь со справочником-владельцем.
	- [ ] Для реквизита *Комментарий* указана размерность — строка неограниченной длины.
	- [ ] Реквизит *Автор документа* заполняется при создании документа при условии, что он не заполнен. Допускается заполнять реквизит в процедуре `ОбработкаЗаполнения()` модуля объекта. Реквизит недоступен для ручного изменения на форме.
	- [ ] Установлен отбор по типу номенклатуры *Услуга* для реквизита *Номенклатура* табличной части.
	- [ ] Расчет значения реквизита *Сумма документа* производится при изменении табличной части. Код выделен в отдельную процедуру.
	- [ ] Расчет суммы по строке производится при изменении реквизитов *Количество* и *Цена*. Код для расчета выделен в отдельную процедуру. Допускается использование экспортной процедуры клиентского общего модуля.
	- [ ] В табличную часть добавлен реквизит *Статья затрат*, который заполняется при изменении реквизита *Номенклатура* табличной части. Директива компиляции для функции заполнения статьи затрат установлена как `&НаСервереБезКонтекста`. Значение реквизита *Статья затрат* доступно для изменения на форме интерактивно.
	- [ ] При формировании движений по регистру *Учет затрат* значение измерения *Статья затрат* заполняется из табличной части.
	- [ ] На форму документа выведена навигационная ссылка для просмотра движений по регистру *Учет затрат* с отбором по текущему документу.
	- [ ] Реквизиты шапки документа расположены в два столбца и выровнены по левому краю.
	- [ ] Реквизиты подвала документа — *Комментарий* и *Ответственный* — равномерно растягиваются при увеличении формы до полноэкранного размера.
	- [ ] В подвале табличной части отображается итог по колонке *Сумма* и префикс *Итого:*.
	- [ ] Движения по регистру *Учет затрат* сворачиваются по статье затрат.
	- [ ] При многократном проведении документа движения регистров замещают предыдущие записи.
4. Учетная политика.
	- [ ] На форму документа выведены навигационные ссылки для просмотра движений документа по регистрам накопления. При нажатии открывается список записей с отбором по текущему документу.
	- [ ] Записывается пустой набор записей регистра *Товары на складах* перед запросом к остаткам регистра.
	- [ ] Накладывается блокировка на регистр *Товары на складах*.
	- [ ] В запросе накладывается отбор по непустому значению поля *Статья затрат*. Отбор накладывается в параметрах виртуальной таблицы.
	- [ ] Обработка результата запроса оптимизирована и выполняется за один цикл. Допускается использование итогов и сворачивание идентичных записей регистра с незаполненным значением статей затрат.
5. Поступление денежных средств.
	- [ ] Документ вводится на основании документа *Реализация товаров и услуг*, при этом заполняются реквизиты *Вид операции, Плательщик, Документ-основание и Сумма документа*.
	- [ ] Реквизит *Плательщик* имеет составной тип и включает в себя справочники — *Сотрудники, Банки и Контрагенты*.
	- [ ] При изменении вида операции для реквизита составного типа *Плательщик* назначается соответствующий тип значения справочника.
	- [ ] Для реквизита *Договор контрагента* настроена связь со справочником-владельцем.
	- [ ] Реквизит *Автор документа* заполняется при создании документа при условии, что он не заполнен. Допускается заполнять реквизит в процедуре `ОбработкаЗаполнения()` модуля объекта. Реквизит недоступен для ручного изменения на форме.
	- [ ] При создании документа заполняются значения по умолчанию для реквизитов *Вид операции* и *Тип денежных средств*. При открытии документа устанавливается видимость необходимых реквизитов.
	- [ ] Документ не проводится и не создает движения по регистрам при нулевом значении реквизита *Сумма документа*.
	- [ ] При изменении вида операции на значения *Получение наличных в банке* или *Возврат от подотчетника* и при заполненном значении реквизита *Договор контрагента* задается вопрос на подтверждение очищения договора.
	- [ ] При изменении реквизита *Плательщик* со типом контрагента *Поставщик* на контрагента с типом *Клиент* и заполненном значении договора, задается вопрос на подтверждение очищения договора.
	- [ ] При изменении реквизита *Плательщик* с типом контрагента *Поставщик* на контрагента с таким же типом и при заполненном значении договора, договор очищается.
	- [ ] При многократном проведении документа движения регистров замещают предыдущие записи.
	- [ ] При проведении документа с типом денежных средств *Наличные* формируется движение с видом *Приход* по регистру *Денежные средства*, все измерения и ресурсы регистра заполнены.
	- [ ] При проведении документа с типом денежных средств *Безналичные* формируется движение с видом *Приход* по регистру *Безналичная оплата*, все измерения и ресурсы регистра заполнены.
	- [ ] Перед формированием движений по регистрам не записываются пустые наборы регистров накопления.
6. Расход денежных средств.
	- [ ] Документ вводится на основании документов *Реализация товаров и услуг*, *Поступление товаров* и *Поступление услуг* . При этом заполняются реквизиты *Вид операции, Покупатель, Документ-основание и Сумма документа*.
	- [ ] Реквизит *Получатель* имеет составной тип и включает в себя справочники — *Сотрудники, Банки и Контрагенты*.
	- [ ] При изменении вида операции для реквизита составного типа *Покупатель* назначается соответствующий тип значения справочника.
	- [ ] Для реквизита *Договор контрагента* настроена связь со справочником-владельцем.
	- [ ] Реквизит *Автор документа* заполняется при создании документа при условии, что он не заполнен. Допускается заполнять реквизит в процедуре `ОбработкаЗаполнения()` модуля объекта. Реквизит недоступен для ручного изменения на форме.
	- [ ] При создании документа заполняется значение по умолчанию для реквизита *Вид операции*. При открытии документа устанавливается видимость необходимых реквизитов.
	- [ ] Документ не проводится и не создает движения по регистрам при нулевом значении реквизита *Сумма документа*.
	- [ ] При изменении вида операции на значения *Взнос наличными в банк* или *Выдача денег подотчетнику* и при заполненном значении реквизита *Договор контрагента* задается вопрос на подтверждение очищения договора.
	- [ ] При изменении реквизита *Получатель* с типом контрагента *Поставщик* на контрагента с типом *Клиент* и заполненном значении договора, задается вопрос на подтверждение очищения договора.
	- [ ] При изменении реквизита *Получатель* с типом контрагента *Поставщик* на контрагента с таким же типом и при заполненном значении договора, договор очищается.
	- [ ] При многократном проведении документа движения регистров замещают предыдущие записи.
	- [ ] При проведении документа формируется движение с видом *Расход* по регистру *Денежные средства*, все измерения и ресурсы регистра заполнены.
	- [ ] При проведении документа не осуществляется контроль отрицательных остатков по регистру *Денежные средства*.

## **Отчеты**

1. Отчет по прибыли.
	- [ ] Финансовый результат отображается зеленым цветом в случае прибыли и красным — в случае убытка.
	- [ ] Использован стандартный период и корректно настроено заполнение параметров начала и конца периода.
	- [ ] На форму отчета выведен отбор по статье затрат.
